MusicD Server

Your own music files, played to Sonos

A small server on a machine you own scans your music folder, and every Sonos room in the house plays from it — with MusicD Remote's interface in a browser, on an iPhone home screen, or in the Android app. No Roon, no Plex, no accounts.

v0.3.7 Docker MIT Sonos only Hi-res → 24/48

How it works

The interface is MusicD Remote's. Underneath, instead of a Roon Core, there is your library and the Sonos control from Caldera Sonos Bridge.

→
MusicD Serverlibrary, queue, conversion
→
Sonosevery room and group

Tracks go into the speaker's own Sonos queue, so playback is gapless and a skip is instant. Each speaker fetches the audio straight from the server — as the file itself when it can play it, as FLAC 24/48 when it can't.

🏠Home, the way MusicD does it

Not played in six months, Album of the day, Smart Picks, random albums, your whole library and genres — rows you can reorder or switch off.

🔍Instant search & focus

Search albums and artists as you type. Sort and focus the library by genre, decade, format, sample rate, bit depth or date added.

📰Write-ups & reviews

Album and artist stories from Wikipedia and Qobuz's editorial pages, and the Pitchfork score with a link to the review — no account needed.

〰Waveform

The seek bar draws the shape of the track, measured from your file and kept, so it is instant after the first play.

📤Share card

The record as an image, where to hear it and where to read about it, and three acts worth hearing next — the ones you own play straight away.

📻Random Album Radio

When a room's queue runs out, another whole album you haven't played lately goes on. Per room.

🔊Rooms and groups

Volume per speaker, group and ungroup rooms, shuffle and repeat, and move what's playing to another room.

📺Wall display

A full-screen now-playing page for a TV or tablet at /display, with reviews, artist stories and more from your library.

🎶Playlists

Playlists you build, Dynamic Playlists that follow a saved focus, and sharing in MusicD Remote's own format.

The 24/48 rule

Sonos S2 plays up to 24-bit / 48 kHz. Everything within that goes to the speaker untouched; everything above it is brought down to 24/48 and stays lossless.

Your fileWhat the speaker gets
FLAC, ALAC, MP3, AAC, Ogg, 16-bit WAV/AIFF ≤ 24/48The file itself, byte for byte — bit-perfect
Above 24/48 (88.2–384 kHz, 32-bit)FLAC 24-bit / 48 kHz
DSD (DSF, DFF)FLAC 24-bit / 48 kHz
APE, WavPack, WMA Lossless, Opus, 24-bit WAVFLAC at the file's own rate and depth
More than two channelsFolded down to stereo

Resampling is ffmpeg with the SoX resampler at high precision and triangular dither. A converted track plays while it is still being written, the next tracks are prepared ahead, and replays come from a cache (4 GB by default).

Install with Docker

On an always-on Linux machine on the same network as your speakers — a NAS, a Raspberry Pi 4/5 on a 64-bit OS, a home server. Fill in your music folders and time zone and copy the command.

Music folders on this machine 

      


      

        --network host is required. Speakers are found by multicast, which does not cross
        Docker's default bridge network, and they fetch audio from this machine's own address.
        Docker Desktop for macOS and Windows has no real host networking, so this needs a Linux host.
      

      

        Keep the musicd-server-data volume. It holds the library database, play history,
        playlists, settings and the artwork and conversion caches. The command above is a swap, not a
        fresh start — re-run it to update.
      

      

        More than one music folder? Add each one above. A single folder is mounted as
        /music; with several, each becomes its own folder inside it —
        /mnt/nas/Albums as /music/Albums, /mnt/usb/Vinyl as
        /music/Vinyl — and the scan reads them all as one library. All are
        mounted read-only. Adding or removing a folder later is the same command re-run; albums
        in a folder that is gone drop out at the next scan.

On your phone

    
The same interface everywhere, because it comes from the server.

    

      

        iPhone & iPad
        
Add to Home Screen

        
Open http://<server-ip>:3500 in Safari, tap Share → Add to Home
           Screen. It opens full screen like an app — the same arrangement as MusicD Remote.

      

      

        Android
        
The MusicD app

        
Enter the port and it finds the server on your Wi-Fi by itself — or type the address.
           On top of the interface it adds lock-screen and notification controls, volume keys that
           move the room's volume, a now-playing widget, a random-album Quick Settings tile and a
           proper share sheet for the share card.

        
Download the APK
           — the newest build is in dist/. Sideload on Android 8.0 or newer. Until the
           repository has its signing key, builds are debug-signed: to install a newer one, uninstall
           the old one first.

      

    

  






  

    
Environment variables

    
All optional; pass any with -e NAME=value. Everything else is in the
       app's Settings and kept in the data volume.

    

      

        
VariableDefaultPurpose

        
PORT3500The interface, the API, and where speakers fetch audio.

        
TZUTCAlbum of the day and Smart Picks change over at local midnight.

        
SONOS_HOSTS—A speaker's IP, for when multicast discovery is unreliable. One is enough.

INCLUDE_ZONES—Offer only these rooms, e.g. Kitchen,Study.

        
EXCLUDE_ZONES—Offer every room except these.

TRANSCODE_CONCURRENCY2Tracks converted at once.

        
DEBUG—Log every API call.

      

    

  






  

    
Troubleshooting

    
http://<server-ip>:3500/api/health answers without signing in;
       /api/status (signed in) says what the server can see. Forgot the password?
       docker exec musicd-server node reset-password.js, then create the account again.

    

      

        No rooms
        
"No Sonos rooms found yet"

        
Check the container is on host networking and on the same subnet as the speakers, then
           look at sonos.error in /api/status. Setting
           SONOS_HOSTS to one speaker's IP skips discovery.

      

      

        Silence
        
A room skips every track

        
The speakers can't reach the server. On a machine with several network interfaces set
           SERVER_IP to its LAN address, and check nothing blocks the port.

      

      

        No albums
        
The library is empty

        
/api/status shows music_dir and index_count. Check
           the -v …:/music:ro mount and that the folder is readable.

      

      

        Hi-res
        
96 kHz files won't play

        
/api/health must say "ffmpeg": true. The Docker image includes it;
           a hand-run server needs ffmpeg on the PATH.
